# Jazzer.js с возможностью автоматического завершения по таймауту покрытия (-exit_on_time)

Данный репозиторий представляет собой специализированную сборку [jazzer.js](https://github.com/CodeIntelligenceTesting/jazzer.js), в которую добавлен **механизм автоматического завершения фаззинга**, если в течение заданного времени не происходит прироста новых путей (покрытия).

Изначальная модификация исходного кода `libFuzzer` (является официальным компонентом экосистемы LLVM и разрабатывается в рамках проекта compiler-rt) была взята из чата сообщества ФСТЭК России и ИСП РАН в области разработки безопасного и качественного ПО ["Динамика::Доверенная разработка"](https://t.me/sdl_dynamic/9413).

Соответствующий патч также размещен в каталоге `patches/`, на случай если потребуется пересборка LLVM другой версии.

В проект встроен готовый тулчейн **LLVM 20** и настроена автоматическая сборка, что позволяет быстро развернуть окружение, собрать нативный аддон и проводить фаззинг JavaScript/TypeScript приложений без необходимости вручную компилировать тяжелые зависимости.

## Системные требования

- Git (Cистема управления версиями)
- Linux x86_64
- Базовые утилиты сборки (make, patch и т.д.)

## Автоматическая настройка и сборка
В проекте предусмотрен скрипт автоматизации, который самостоятельно применяет патчи, устанавливает зависимости Node.js, компилирует TypeScript-код и собирает нативный аддон фаззера, используя встроенный тулчейн.
1. Сделайте скрипт исполняемым:
```bash
chmod +x ./scripts/setup_fuzz.sh
```
2. Запустите скрипт из корня проекта:
```bash
./scripts/setup_fuzz.sh
```

## Запуск фаззинга
После завершения настройки вы можете запустить ваш целевой JavaScript/TypeScript файл для фаззинга.
Для использования функции автоматического завершения при отсутствии новых путей передайте флаг **-exit_on_time=<секунды>** в секции аргументов libFuzzer:

```bash
node jazzer.js/packages/core/dist/cli.js /path/to/your/fuzz.js --sync /path/to/your/artifacts/dir -- -exit_on_time=15 -print_final_stats=1 /path/to/your/corpus
```

### Разбор параметров
#### Позиционные аргументы (до --)
- node jazzer.js/packages/core/dist/cli.js - точка входа (CLI-скрипт) движка jazzer.js.

- /path/to/your/fuzz.js - путь к целевому скрипту фаззинга, экспортирующему функцию fuzz(buffer).

- /path/to/your/artifacts - директория, куда фаззер сохраняет найденные интересные тест-кейсы, падения (crashes), таймауты и т.д.

#### Флаги фреймворка (между целью и --)
--sync - принудительно запускает фаззер в синхронном режиме, обеспечивая предсказуемую обработку буферов и корректную интеграцию с инструментами сбора покрытия.

#### Нативные флаги libFuzzer (после --)
Всё, что передается после двойного дефиса, транслируется напрямую в нативный движок libFuzzer:
- -exit_on_time=15 - автоматически завершает фаззинг, если в течение 15 секунд не обнаруживается новых путей покрытия кода.
- -print_final_stats=1 - выводит подробную статистику выполнения по завершении работы (общее число итераций, скорость exec/s, пиковое потребление памяти rss и т.д.).
- /path/to/your/corpus (аргумент в самом конце) - путь к директории с начальным seed-корпусом (валидными примерами входных данных).

### Обязательные каталоги и требования
1. Каталог артефактов (artifacts) - Обязателен  
   **Назначение:** хранит вновь обнаруженные тест-кейсы, вызывающие падения или новые ветки выполнения.  
   **Что будет**, если пропустить / не создать:
- Если директория не существует на диске, libFuzzer попытается создать её автоматически в текущей рабочей директории.
- Если отсутствуют права на запись или пути указаны неверно, найденные тест-кейсы не будут сохранены для последующего анализа и трекинга покрытия.

2. Каталог корпуса (corpus) - Опционален, но рекомендуется  
   **Назначение:** содержит валидные файлы-образцы (seed-корпус). Мутация структурированных корректных данных в разы эффективнее генерации случайного мусора с нуля.  
   **Что будет**, если пропустить:
- Фаззер выведет сообщение "*A corpus is not provided, starting from an empty corpus*" и начнет генерацию целиком со случайных байтов. Для сложных форматов (парсеры, протоколы) это существенно замедлит процесс исследования внутренней логики программы.


## Сбор покрытия после фаззинга и генерация отчетов о покрытии кода
Поскольку `jazzer.js` работает в изолированном контексте выполнения, стандартные флаги покрытия V8 не могут быть прочитаны прямо во время цикла фаззинга. Вместо этого покрытие рассчитывается путем повторного прогона целевого скрипта по накопленным тест-кейсам (начальный корпус + обнаруженные артефакты) с помощью инструмента c8.

Ниже приведен один из рекомендуемых вариантов реализации такого сбора покрытия с помощью универсального скрипта-раннера. Вы можете адаптировать его или использовать любые другие удобные вам инструменты.

**Примечание:** данный подход является примером. Вы вольны применять любые кастомные скрипты, обертки, альтернативные инструменты анализа покрытия (например, `nyc`) или организовывать пайплайн, учитывая архитектуру вашего проекта.

Допустим, вы запустили фаззинг со следующим распределением путей (где корпус указан в качестве аргумента `libFuzzer` в самом конце):

```bash
node jazzer.js/packages/core/dist/cli.js /path/to/your/fuzz.js /path/to/your/artifacts --sync -- -exit_on_time=15 -print_final_stats=1 /path/to/your/corpus
```
В результате работы фаззера:
1) В каталоге /path/to/your/corpus находились базовые сиды.
2) В каталоге /path/to/your/artifacts сохранились новые уникальные инпуты, найденные движком.

Чтобы проиграть оба каталога (и корпус, и артефакты) на вашей цели под управлением c8, вы можете использовать универсальный скрипт run-coverage.js (./coverage/run-coverage.js), принимающий пути аргументами:

Используя описанный выше запуск фаззинга, вы можете собрать и вывести отчет о покрытии в терминал с помощью следующей команды:

```bash
npx c8 --include "**/fuzz.js" --reporter=text node ./coverage/run-coverage.js /path/to/your/fuzz.js /path/to/your/artifacts /path/to/your/corpus
```

Чтобы сформировать красивый интерактивный HTML-отчет о покрытии кода с помощью c8, вам не нужно менять скрипт-раннер - достаточно изменить флаг --reporter в команде запуска.
```bash
npx c8 --include "**/fuzz.js" --reporter=html node ./coverage/run-coverage.js /path/to/your/fuzz.js /path/to/your/artifacts /path/to/your/corpus
```
